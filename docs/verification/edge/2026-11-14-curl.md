# Edge header evidence, 2026-11-14 (M3-5, PV-D9)

Read-only requests against production (`https://pequeverso.com`, build served at the time of the
capture: the standalone app behind Cloudflare). Production is not changed by this task; this file
is the "before" evidence for the config shipped in M3-5. Captured from Buenos Aires
(`cf-ray` suffix `EZE`). `report-to` / `nel` (Cloudflare network error logging) and any
`set-cookie` lines are stripped; nothing else is edited. Repeat the same commands after M7 and the
owner dashboard steps and add a dated file next to this one.

## Findings

1. `/_next/static/*` is already `public, max-age=31536000, immutable` end to end (origin header,
   `cf-cache-status: HIT`, `age` 410487 s on the chunk and 410488 s on the stylesheet). The 4 h figure in audit F-07 does not reproduce for
   `/_next/static`.
2. The 4 h value (`max-age=14400`) on `/media/*`, `/fonts/*` and `/favicon.ico` comes from files
   served straight from `public/`. Those responses carry `x-turbo-charged-by: LiteSpeed` and none
   of the headers from `config/edge-rules.json` (no HSTS, nosniff, CSP, no immutable
   `Cache-Control`; compare the Next-served responses, which carry `platform: hostinger`).
   Hypothesis: Hostinger's LiteSpeed answers static files from disk without passing through the
   Node server, so `headers()` never applies; Cloudflare then fills `Cache-Control` with its
   Browser Cache TTL default (14400 s) because the origin sends none. Consequence: the
   `immutable-media` and `immutable-fonts` rules in `config/edge-rules.json` are inert in
   production (they only apply when Next serves the path). Not provable from outside the account;
   the owner confirms with the dashboard steps in `docs/deployment.md` ("Edge settings"). Captured
   `age`: media 405 s, font 367 s (both `cf-cache-status: HIT` after a first MISS). The OG images are
   versioned with `?v=` rather than content-hashed, so a one-year browser TTL on them would need
   the `?v=` bump discipline; the Cache Rule in `docs/deployment.md` covers only `/media/` and
   `/fonts/`.
2b. `/robots.txt` is a different case. It comes through Next (it has HSTS, nosniff, CSP, `platform:
   hostinger`, `x-nextjs-cache: HIT`) and its origin `Cache-Control` is `no-cache`-class, yet
   the response shows `max-age=14400`: Cloudflare's Browser Cache TTL overrides the origin value
   (hypothesis; fixed by "Respect Existing Headers", `docs/deployment.md`).
3. HSTS is `max-age=300` (the previous config). `https://www.pequeverso.com/` answers 308 to the
   apex over valid TLS; `http://pequeverso.com/` answers 301 to https.
4. A second, Hostinger-added `content-security-policy: upgrade-insecure-requests` accompanies the
   site policy on every Next-served response. Two enforced policies intersect, so it is harmless.
5. Cloudflare injects `static.cloudflareinsights.com/beacon.min.js` into HTML for browser
   user agents only (absent for the default curl agent, present with a browser agent). The
   `/cdn-cgi/scripts/.../email-decode.min.js` script is Cloudflare Email Address Obfuscation.
